# 손톱 사이즈 측정 정확도 분석과 개선 계획

작성: 2026-08-12 · 코드 실사 기준 (mobile/services/nailMeasurement, ml/inference/server.py)

## 현재 파이프라인 요약

1. 촬영: 사용자가 신용카드+손톱을 화면 가이드에 맞춰 촬영 (단일 프레임)
2. 서버(DeepLabV3+ ResNet101, 800×800): 중앙 정사각 크롭 → 리사이즈 → 손톱 세그멘테이션 마스크
3. 스케일: `cardPixelsInModel = 800 × (가이드폭 / (화면높이 × 3/4))` — **가이드 기반 추정**
4. 측정: 마스크에서 손톱 폭(px) → `mm = px × (85.6 / cardPixelsInModel)`

## 정확도를 갉아먹는 원인 (영향도 순)

### 🔴 P0 — 스케일 기준(카드)을 "측정"하지 않고 "가정"한다 (지배적 오차)

`cardPixelsInModel`은 이미지에서 카드를 찾아 잰 값이 **아니다**. "사용자가 카드를 화면 가이드에 완벽히 맞췄다"는 가정 + `CAMERA_SENSOR_ASPECT_RATIO=3/4` 고정값으로 계산한 **기하학적 추정치**다.

- 카드를 가이드보다 5% 크게/작게 잡으면 → 스케일 5% 오차 → **모든 손톱이 같은 비율로 오차**
- 기종마다 실제 센서/프리뷰 비율이 달라 3/4가 안 맞으면 → 전 측정 계통 오차
- 카드가 유일한 기준이라, 이 하나가 틀리면 전부 틀린다

이것이 정확도의 **단일 최대 병목**이다.

### 🔴 P0 — 카드와 손톱의 동일 평면·거리 가정

카드의 mm/px는 카드가 놓인 평면에서만 유효하다. 손톱이 카드보다 카메라에 가까우면(손을 들면) 손톱이 더 크게 찍혀 **과대측정**된다. 현재 UX는 이 coplanarity를 강제하지 않는다.

### 🟠 P1 — 손톱 폭 계산이 회전에 취약 + 두 경로 불일치

- 서버 `/api/measure`: `boundingRect`의 폭(축 정렬 bbox width) 사용 → 손가락이 기울면 폭 과대
- 클라이언트 `imageProcessor.ts`: 행별 최대 폭 → 서버와 다른 값
- 올바른 측정은 **손톱 장축에 수직인 폭**(minAreaRect 또는 PCA축 기준). 지금은 축 정렬이라 기울기에 오차

### 🟠 P1 — 하드 임계값 0.5, 서브픽셀 없음

마스크 확률을 0.5로 자른 정수 픽셀 폭. 800공간에서 1px ≈ 0.11mm. 확률 가중 경계(서브픽셀)로 정밀도 향상 여지.

### 🟡 P2 — 중앙 정사각 크롭이 정보 손실 + 중앙 가정

프레임 가장자리의 카드/손톱은 크롭으로 잘려나갈 수 있다.

### 🟡 P2 — 단일 프레임, 다중 프레임 평균/이상치 제거 없음

한 장으로 판정. N프레임 중앙값을 쓰면 노이즈·손떨림 완화.

### ⚪ 문서 불일치 (버그 아님)

`SIZING_LOGIC.md`는 640 기준으로 서술돼 있으나 코드는 800(types.ts, server.py). 문서 갱신 필요.

## 개선 로드맵 (영향×노력 순)

### Tier 1 — 카드를 실제로 감지·측정 (재학습 불필요, 최대 ROI)

서버(OpenCV)에서 카드 사각형을 검출:
- 엣지→윤곽→사각형 근사→종횡비 1.586 검증으로 카드 4꼭짓점 검출
- **호모그래피로 정면 정렬(rectify)** → 카드 픽셀폭을 정확히 측정 + **원근 기울기까지 보정**
- 이 정렬 평면에서 손톱 폭을 재면 스케일·기울기 동시 해결

→ 가정 기반 스케일을 실측 스케일로 대체. 모델 재학습 없이 즉시 적용 가능. **1순위.**
대안: 모델에 "card" 세그 클래스 추가(재라벨·재학습 필요) — 후순위.

### Tier 2 — 손톱 폭을 올바르게

- 클라이언트/서버 측정 경로를 **서버 단일 경로로 통일**(OpenCV 보유)
- 축 정렬 bbox 대신 **minAreaRect/PCA축 수직 폭**
- 확률 가중 서브픽셀 경계

### Tier 3 — 강건성

- 다중 프레임 촬영 + 중앙값
- coplanarity UX(카드·손톱을 같은 평면에 평평히, 폰을 수평으로) 가이드
- 측정 범위·이상치 검증 확장(현재 6–22mm 경고만)

### Tier 4 — 정확도 측정 하네스 (사실 이게 선행되어야 함)

현재 **정답값 대비 실제 오차를 재는 루프가 없다.** 캘리퍼로 실측한 손톱폭 + 촬영 이미지 세트를 만들어, 각 변경 전후 오차%를 측정해야 개선이 검증 가능하다. 없으면 "정확도 개선"은 추측이다.

## 권장 착수 순서

1. **Tier 4 하네스 먼저** — 테스트 이미지 몇 장 + 캘리퍼 실측으로 현재 오차 baseline 확정
2. **Tier 1 카드 검출·호모그래피** — 지배적 오차 제거
3. Tier 2 폭 계산 정정 → Tier 3 강건성

## 진행 상황 (2026-08-12, 실촬영 검증 기반)

### 실측 대조로 확인된 것 (usertest, 왼/오 5손가락 캘리퍼 실측)
- 앱 측정값이 **+15~33% 계통 과대측정** → 지배적 오차 = **카드 스케일**(가정 기반). 사용자가 카드를 가이드에 완벽히 못 맞춘 것과 일치.
- 오른손 검지 4.7mm(실측 11) = 별개 세그멘테이션/분류 버그.

### CV 카드 검출 실험 (실촬영)
- "손을 카드 위" 자세: 4장 중 3장 미검출, 1장 오검출 → **CV 검출 불가(구조적)**. 저대비가 아니라 손 가림+기울기+배경 잡음 때문.
- "카드 온전 노출" 자세: 검출 성공(종횡비 오차 0.005~0.03, 박스 정확). 검출 스케일로 3손톱 측정 11.6/11.8/8.5mm vs 실측(11,12,10,9) → **오차 +15~25% → ±5~6%로 개선**.

### 결정: 경로 A (UX 변경 — 카드를 가리지 않는 자세)
"손을 카드 위" → **"카드 온전 노출 + 손톱을 카드 바로 아래"**. 재학습 불필요.

### 구현 상태
- [x] Lambda 카드 실측 검출(detect_card) — 배포·라이브 검증(합성 detected)
- [x] 손톱 폭 회전 불변(measure_nail_width) — 배포·라이브. bbox 3.5%→0.4%
- [x] 모바일 클라이언트 배선 — 검출 성공 시 card_width_pixels_detected로 스케일 (커밋)
- [x] 새 자세 촬영 가이드(CameraGuideOverlay/CameraScreen) — 손톱을 카드 아래로, 문구 교체 (커밋)
- [x] 서버 nail_filter 파라미터(none=새 자세, 카드 박스 필터 끔) (커밋, 미배포)
- [ ] **앱 재빌드·출시** — 위 모바일 변경(배선+가이드)은 앱 빌드가 있어야 사용자 반영. 현재 기기 앱 RN 0.73.6 ≠ 저장소 0.85.0로 로컬 빌드 불가. **앱팀 파이프라인 필요.**

- [ ] "카드+손톱 붙인" 잘 프레이밍된 사진으로 4/4 + 정확도 최종 확인
- [ ] 오른손 검지 세그멘테이션 버그 원인 규명

### 남은 리스크
- 세그멘테이션 모델은 "손톱을 카드 위" 옛 자세로 학습됨. 새 자세(손톱이 바닥/피부 배경)에서 마스크 품질이 다소 떨어질 수 있음(폭 값은 실측 근접이라 실용 수준). 필요 시 새 자세 데이터로 재학습.
- 중앙 정사각 크롭이 카드·손톱을 함께 담으려면 둘을 붙여 중앙에 둬야 함(가이드로 유도).
