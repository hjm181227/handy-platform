## Wave 2 — 실결제 리허설 (사장님 30분 + 나 모니터링 · Wave 1과 병행 가능)

### 2-1. 프로덕션 실결제 → 반품 → 실환불 사이클
테스트 키로는 검증 불가한 유일 구간. 절차:
1. (셀러) 기존 상품 하나 `salePrice`를 1,000원으로 임시 인하
2. (개인 계정) 실카드로 구매 → 토스 대시보드에 결제 확인
3. (셀러) 주문 확인 → 배송중 → **배송완료** 처리
4. (개인 계정) 마이페이지 → 반품·교환 → **반품 신청** (사유 입력)
5. (셀러) 판매자센터 → 반품·교환 → **승인** ("전액 환불 즉시 진행" confirm)
6. 확인 3가지: ① 토스 대시보드에 취소(환불) 기록 ② 구매자 알림함에 환불 알림
   ③ 상품 재고 +1 복원
7. (셀러) salePrice 원복
- 이상 발생 시 즉시 중단하고 상태 공유 — 관리자 쪽 수동 처리 경로로 복구 가능

## Wave 3 — 외부 의존 해소 후 (심사·앱팀 완료 시점)

### 3-1. 알림톡 발송 연동 (나, 1~2일) — 0-1 심사 통과 후
- `NaverSensService`에 알림톡(`/alimtalk/v2`) 발송 메서드 추가 (기존 서명 로직 재사용)
- `OrderNotificationService` 팬아웃에 알림톡 채널 추가 (인앱과 병행, 실패해도 인앱은 유지)
- `notificationSettings` 수신 동의 게이트 + 발송 이력·실패 재시도(1회)
- 템플릿 코드 5종 매핑, 스테이징 테스트 번호로 검증 후 배포

### 3-2. 손톱 측정 UX + 앱 출시 (나 + 앱팀, 2~3일) — 0-2 파이프라인 확보 후
- 콜드스타트: 측정 화면 진입 시 `/health` 워밍업 + 5초 경과 시 "서버 준비 중(최대 30초)" 안내
- ML API에 재시도(503/502 백오프)·60초 타임아웃 (기존 `withRetry` 인프라 적용)
- 에러 화면에 "다시 촬영" 버튼 (현재는 같은 사진 재분석만 가능해 무한 실패 루프)
- 첫 진입 온보딩 3스텝 (카드 배치 예시·좋은/나쁜 예)
- 측정 결과 → 커스텀 주문서 사이즈 자동 입력 연결 검토

### 3-3. 가상계좌 개방 (사장님+나, 0.5일) — 1-3 마운트 후
- (사장님) 토스 대시보드에 웹훅 URL 등록
- (나) 스테이징 웹훅 테스트 → DEPOSIT_CALLBACK 처리 확인 → 가상계좌 거부 가드 해제
- (공동) 프로덕션 가상계좌 소액 실입금 테스트 1회

### 3-4. 비밀번호 재설정 (나, 1일) — 이메일 발송 수단 결정 후
- 발송 수단: SES(도메인 인증 필요) 또는 알림톡으로 대체(휴대폰 인증 기반 재설정 — 이메일 불필요, **권장**)
- 알림톡 방식이면: 휴대폰 인증(기존 SENS) → 재설정 토큰 → 새 비밀번호. 이메일 인프라 자체를 건너뜀
